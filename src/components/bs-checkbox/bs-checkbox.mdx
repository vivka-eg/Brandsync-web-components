## Overview

A single checkbox with its label, for a binary choice or one item within a group of independent
choices.

**When to use**
- A single standalone binary setting (e.g. "Remember me", "I agree to the terms").
- One item within a set of independent, non-exclusive choices (a checkbox group/list).
- `indeterminate` for a "select all" checkbox representing a partially-selected group.

**When not to use**
- A single mutually-exclusive choice from a set -- use a radio group instead.
- An on/off setting that takes effect immediately (no explicit form submission) -- use `bs-switch`.

## Indeterminate

`indeterminate` shows a minus icon instead of a check, and takes visual precedence over `checked`
regardless of that prop's value -- the same way native `<input type="checkbox">` behaves. Unlike
`checked`, native checkboxes have no `indeterminate` HTML attribute; it can only be set as a JS
property, which this component does internally on the native input it wraps. Clicking the checkbox
clears `indeterminate`, same as a native checkbox.

## Error

This component's spec has no error message text of its own (unlike `bs-input`'s `error: string`),
so `error` is a plain boolean that only changes the border/label color.

## Accessibility

- Renders a real `<input type="checkbox">`, visually hidden (`opacity: 0`, not `display: none`) so
  it stays focusable and keyboard-operable (Space toggles it, same as any native checkbox).
- The native input is wrapped in a `<label>` together with the visual box and label text, so
  clicking anywhere in the component toggles it -- no separate `for`/`id` wiring needed.
- `aria-checked="mixed"` is set on the native input while `indeterminate` is true, so assistive
  technology announces the partially-selected state (native `.indeterminate` alone isn't reliably
  announced by all screen readers).
- `disabled` sets the native `disabled` attribute, which removes the control from the tab order and
  is announced by assistive technology automatically -- no separate `aria-disabled` is added.
- **Required whenever the default (label) slot is empty:** set `ariaLabel` (e.g. a bare "select
  row" checkbox in a table). Setting a plain `aria-label` HTML attribute on the `<bs-checkbox>`
  host does **not** work -- that attribute never crosses into the shadow DOM, so the actual
  focusable native `<input>` stays nameless. Same prop/pattern as `bs-button`'s and `bs-tab`'s
  identical `ariaLabel` prop.
