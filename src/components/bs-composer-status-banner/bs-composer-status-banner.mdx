## Overview

A full-width status banner for use directly above `bs-composer`, surfacing a message about the
composer's current state (e.g. a send failure, an informational notice) with an optional
"Continue"-style action button and an optional close button.

**When to use**
- A message tied to the composer itself (send failed, rate-limited, draft restored, etc.) that
  needs to sit directly above it.

**When not to use**
- A toast/snackbar notification unrelated to the composer — this component is not self-dismissing
  and has no positioning of its own (it's a static block, not an overlay).

## With action button

Set `showButton` to render a secondary action alongside the message (e.g. "Retry"). Its color
follows `type`, except `type="neutral"`, whose action button is outlined instead of solid since
there's no strong "neutral action" brand color to fill it with.

## Above bs-composer

The intended real-world placement: `bs-attachment-list` goes *inside* `bs-composer` (via its
`attachments` slot), not as a separate element outside it -- only the banner sits outside, tucked
slightly behind the composer's top edge (a negative `margin-bottom` on the banner, matching the
source design) so the two read as one continuous surface instead of two stacked cards with a
visible seam.

## Events

| Event      | Fires when                    | Payload | Cancelable |
| ---------- | ------------------------------ | ------- | ---------- |
| `bsAction` | The action button is clicked   | `void`  | No         |
| `bsClose`  | The close button is clicked    | `void`  | No         |

## Accessibility

- The close button has a fixed `aria-label="Dismiss"` since it's icon-only with no visible text.
- The leading icon is `aria-hidden` — it's decorative, the message text itself conveys the status.
- Both buttons use the standard focus-visible outline (`--bs-border-neutral-focus`), so keyboard
  users get a visible focus ring regardless of `type`.
- This component does not remove itself from the DOM on close — the consumer owns visibility
  (e.g. toggling a prop that controls whether it's rendered at all) in response to `bsClose`.
