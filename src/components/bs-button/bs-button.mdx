## Overview

A clickable action element for the single most important action in a given context.

**When to use**
- The primary call to action on a screen or within a card/modal (e.g. "Book room", "Confirm").
- Secondary, lower-emphasis actions alongside it (use `variant="neutral"`).

**When not to use**
- For navigation between pages — use a link/nav component instead, a button implies an in-page
  action, not a destination change.
- For more than one primary-emphasis action in the same view — pick one, demote the rest to
  `neutral`.

## Neutral button

Lower-emphasis alternative to the primary variant, for secondary actions alongside it (e.g. a
"Cancel" next to a "Confirm").

## Subtle button

A ghost/text-only style for low-priority actions that shouldn't compete visually with the
primary/neutral buttons around them (e.g. an inline "Learn more" next to a form).

<Canvas of={ButtonStories.Subtle} />

## Outlined button

A bordered, transparent-background style for neutral actions that need more visual weight than
`subtle` but shouldn't draw focus away from the primary action (e.g. "Cancel" or "Back").

<Canvas of={ButtonStories.Outlined} />

## Success button

A semantic variant for actions whose outcome is predictable and clearly communicated by the
button itself (e.g. "Approve", "Mark as complete") — per BrandSync guidance, only use `success`
when the button's own label/action conveys that outcome, not to reflect some other element's
visual state.

<Canvas of={ButtonStories.Success} />

## Warning button

A semantic variant for actions that need the user's attention before proceeding (e.g. "Proceed
anyway"), reserved for cases where the action's outcome is predictable and clearly communicated —
not a general-purpose "caution" color for unrelated content.

<Canvas of={ButtonStories.Warning} />

## Info button

A semantic variant for informational actions with a predictable, clearly communicated outcome
(e.g. "View details"), following the same restraint as `success`/`warning` — don't reach for it
just because something nearby happens to be styled as "info".

<Canvas of={ButtonStories.Info} />

## Error button

Destructive actions should always use the error variant, never `neutral` — using `error` signals
the risk of the action (e.g. "Delete account") rather than just adding visual emphasis, per
BrandSync's own destructive-action guidance.

<Canvas of={ButtonStories.Error} />

An optional trailing icon, slotted in after the label, for actions where the icon reinforces a

## Icon-only button

A button can render with only the `icon` slot and no visible label text — the `bs-button--icon-only`
class adjusts padding so the button stays square instead of stretching to fit an empty label. Since
there's no visible text, `aria-label` is required so the button still has an accessible name for
screen readers.

## Component API

<Controls of={ButtonStories.Primary} />

**Customization surface** (see `CONVENTIONS.md` in the repo root for the full convention):
- Slots: default (label), `icon`, `end-icon`
- Shadow parts: `::part(icon)`, `::part(label)`, `::part(end-icon)`
- CSS Custom Properties: `--bs-button-radius`, `--bs-button-height-sm/md/lg`
- `variant` is one of `primary`, `neutral`, `subtle`, `outlined`, `success`, `warning`, `info`, `error`
- `ariaLabel` prop reflects to the native `aria-label` attribute — required for icon-only usage

## Skeleton state

Shown in place of a `bs-button` while its label/action isn't known yet (e.g. still being fetched
from an API), rendered by the separate `bs-button-skeleton` element, sized to match `bs-button`'s
`sm`/`md`/`lg` heights.

## Accessibility

- Renders a native `<button>` internally, so it's keyboard-focusable and activates on
  <kbd>Enter</kbd>/<kbd>Space</kbd> without any extra ARIA wiring.
- `disabled` uses the native `disabled` attribute — this removes the button from the tab order
  and is announced as disabled by screen readers, not just styled to look inactive.
- Icon-only usage (an `icon` slot with no visible label) is supported, but requires passing
  `aria-label` so the button still has an accessible name — this component doesn't infer one for
  you.
- `bs-button-skeleton` adds `role="status"` and `aria-label="Loading"` on its placeholder so
  screen readers announce the loading state; its pulse animation respects
  `prefers-reduced-motion` and is disabled entirely for users who request reduced motion.
