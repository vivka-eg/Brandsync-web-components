## Overview

A clickable, icon-only action element -- the icon-only sibling of `bs-button`, sharing the same 8
visual variants and color language, but always rendering a single icon with no label.

**When to use**
- A compact action where the icon alone is unambiguous (e.g. a close/dismiss control, a toolbar
  action) and adding a text label would take up more space than the context allows.
- The same variant guidance as `bs-button` applies: `primary` for the single most important
  action, `neutral`/`subtle`/`outlined` for lower-emphasis alternatives, `error` reserved for
  destructive/irreversible actions (never `neutral`), `success`/`warning`/`info` only when the
  action's own outcome is predictable and clearly communicated.

**When not to use**
- When the action isn't self-evident from the icon alone -- use `bs-button` with a visible label
  instead, don't rely on a tooltip to compensate for an unclear icon.
- For navigation between pages -- use a link/nav component instead.

## Sizes

Four sizes -- `xs`, `sm`, `md`, `lg` -- render as 16×16px, 40×40px, 44×44px, and 48×48px square
containers respectively, with 8×8px, 16×16px, 20×20px, and 24×24px icons. Padding is 4px at
`xs` and a constant 12px on every side at `sm`/`md`/`lg`. `xs` also uses a smaller corner radius
(`--bs-icon-button-radius-xs`, aliased to `--bs-border-radius-50`) than the other three
(`--bs-icon-button-radius`, `--bs-border-radius-100`) -- the larger radius would look nearly
circular on a box this small. `xs` is a distinct tier meant for compact chip/tag "remove"
controls, not just a smaller toolbar button, verified against a separate Figma redline (EG
BrandSync UI Kit v1.5, node 20731:18427) from the one `sm`/`md`/`lg` were built against.

## Component API

<Controls of={IconButtonStories.Primary} />

**Customization surface** (see `CONVENTIONS.md` in the repo root for the full convention):
- Slots: default (icon content, exactly one icon)
- Shadow parts: `::part(icon)`
- CSS Custom Properties: `--bs-icon-button-radius`, `--bs-icon-button-radius-xs`,
  `--bs-icon-button-size-xs/sm/md/lg`, `--bs-icon-button-icon-size-xs/sm/md/lg`,
  `--bs-icon-button-padding-xs`, plus per-variant background/color/border tokens (see
  `bs-icon-button.css` for the full list)
- `variant` is one of `primary`, `neutral`, `subtle`, `outlined`, `success`, `warning`, `info`, `error`
- `ariaLabel` prop reflects to the native `aria-label` attribute -- **required** for every usage,
  since this component is always icon-only and has no visible label text to fall back on

## Accessibility

- Renders a native `<button>` internally, so it's keyboard-focusable and activates on
  <kbd>Enter</kbd>/<kbd>Space</kbd> without any extra ARIA wiring.
- `disabled` uses the native `disabled` attribute -- this removes the button from the tab order
  and is announced as disabled by screen readers, not just styled to look inactive.
- Always pass `aria-label` -- unlike `bs-button`, this component has no visible label text under
  any configuration, so without it the button has no accessible name at all.
